# 调用日志

> 用请求 ID 定位一次完成调用，核对模型、Token、性能、接入方式和平台费用。

## 调用日志适合排查什么

调用日志用于查看当前项目内已经完成的调用事实，并从列表进入单次详情。项目整体趋势看项目分析，企业财务核对看成本中心。 例如应用反馈一次回答很慢，使用该请求 ID 查看实际模型、Token 和性能，避免凭整日平均值判断这次请求。

> **影响与边界**：当前列表不用于查找未形成完成记录的认证拒绝、权限拒绝或参数校验失败。找不到记录时先按本文最后的排查顺序确认。

## 先锁定项目、模型类型和日期

1. 确认当前项目与发起调用时使用的项目一致。
2. 默认“全部类型”统一展示大语言模型与多媒体调用；需要只看一类时使用类型筛选，详情按该类型显示适用字段。
3. 选择覆盖调用时间的日期范围，单次查询不要超过页面允许范围。
4. 管理角色可按调用账号筛选；普通成员只查看本人有权记录。

## 优先用请求 ID 定位

如果调用响应或业务日志中保存了请求 ID，直接在搜索框输入完整 ID。没有请求 ID 时，再组合调用时间、调用账号、模型和项目 API Key 名称缩小范围。

> **需要注意**：保存请求 ID 是最可靠的联调习惯。时间相近、模型相同的并发请求仅凭时间很难区分。

## 读懂列表中的关键信号

在同一项目中按请求 ID 和时间缩小范围，再进入单次详情。

| 信息          | 帮助判断什么           | 常见误解                   |
| ----------- | ---------------- | ---------------------- |
| 调用账号／调用密钥   | 是谁、通过哪把项目 Key 发起 | 账号身份不会扩大其他账号 Key 的可见范围 |
| 模型名称        | 本次记录的实际模型        | 使用路由时不要只看请求中的路由 ID     |
| 输入／输出 Token | 本次请求和响应规模        | Token 高不等于一定异常，要结合业务内容 |
| 缓存命中／写入     | 缓存是否参与本次调用       | 未命中不代表调用失败             |
| 延迟／吞吐       | 响应等待和生成速度        | 不同模型与请求长度不能只比较单一数字     |
| 消耗模力／费用     | 本次平台侧消耗          | 不包含 BYOK 自有供应商账单       |

## 打开详情还原单次调用

点击记录查看请求 ID、调用时间、账号与 Key、模型、Token、延迟、吞吐、调用路径、请求来源以及页面提供的接入和费用信息。关闭详情后返回原筛选和列表位置。

## 验证路由、BYOK 与故障回退

* 使用路由策略时，核对最终模型和实际接入方式是否符合调度预期。
* 企业配置 BYOK 后，页面才展示平台渠道／BYOK 等接入信息。
* 发生 BYOK 回退时，记录会落到实际承接调用的渠道，并可能产生平台费用。
* 参数错误、权限拒绝和内容安全拒绝不属于供应商故障，不会形成 BYOK 回退。

## 分析慢请求时不要只看延迟

先比较请求规模、输出 Token、首个响应等待和持续生成速度，再与同模型、相近请求规模的记录比较。长上下文、长输出或供应商波动都可能影响结果。

## 需要批量核对时导出

有导出权限时，先将「调用类型」切换为「大语言」，再设置日期、调用账号、模型和搜索条件，点击「导出」选择格式。「全部类型」或「多媒体」下不显示这个导出入口。基础版单次查询与导出均最长31天，企业版最长180天；允许跨月及历史区间，首尾日期均计入，仅访问实际保留的数据。导出沿用当前筛选，不会自动扩大到其他项目或无权限记录；企业费用批量核对应进入成本中心。

## 找不到记录时按顺序检查

1. 确认项目 API Key、模型或路由 ID 都属于当前项目。
2. 确认模型类型、日期、调用账号和搜索条件没有过滤掉记录。
3. 确认调用已经完成，而不是在认证、权限或参数校验阶段被拒绝。
4. 确认当前角色具有相应日志范围；必要时请项目管理员核对。
5. 仍无法定位时保留请求 ID、时间和项目，提交给技术支持排查。
