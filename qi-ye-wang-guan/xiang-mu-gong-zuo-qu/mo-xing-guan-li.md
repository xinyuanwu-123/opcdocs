# 模型管理

> 理解项目模型限制，比较模型能力与价格，并维护当前项目真正可调用的模型范围。

## 模型管理控制的是当前项目

页面维护当前项目可以继续使用企业全部可用模型，还是只使用允许清单。企业 BYOK 密钥在企业管理中配置，路由调度在路由策略中配置。 例如只允许研发项目使用已评估的模型时，在这里收窄项目允许范围。模型 ID 是接口请求的 model 字段，展示名称方便阅读，两者不要混用。

## 先看清模型限制状态

先确认“全部可用模型”或指定模型范围，再检查目标模型。示例价格不作为实时报价。

| 模型限制 | 当前项目可调用范围  | 企业新增模型后的结果            |
| ---- | ---------- | --------------------- |
| 关闭   | 企业当前全部可用模型 | 新增平台渠道模型自动进入项目范围      |
| 开启   | 仅允许清单中的模型  | 新增平台模型和 BYOK 模型都不自动加入 |

> **需要注意**：新企业的 Default Project 默认使用全部可用模型；已有项目保留各自的设置。先核对当前项目实际状态，再决定是否调整范围。

## 筛选并比较候选模型

1. 在大语言模型和多媒体模型之间选择类型。
2. 按模型 ID、厂商和上下文长度缩小列表。
3. 比较上下文、最大输出、输入价格、输出价格和缓存读取价格。
4. 打开模型详情查看模型 ID、厂商、接入方式、上下文、最大输出和价格等信息。

> **影响与边界**：价格显示“起”表示实际价格可能受模型、渠道或使用条件影响；币种不同的价格不要直接相加。

## 需要固定模型范围时启用限制

启用模型限制后，项目只允许清单内模型。先添加业务正在使用的模型，再让成员或服务切换到受控范围，避免启用后立刻阻断现有调用。

## BYOK 模型为什么可能没有出现

1. 确认企业 BYOK 配置已保存，并用目标模型的实际调用核对连接是否可用。
2. 确认该供应商模型进入企业可用模型目录。
3. 模型限制开启时，将目标模型加入当前项目允许清单。
4. 确认当前成员的项目关系、角色、凭证和用量限额允许调用。

## 最终可调用范围还会继续收敛

项目模型范围决定项目允许使用的模型；具体账号完成调用还需要有效的项目访问权、调用凭证和用量限额。主账号和系统管理员按账号级身份获得项目治理权限，仍须遵守项目状态、模型可用性与凭证范围。

## 移除模型前检查引用影响

移除被路由策略等配置引用的模型时，页面会展示影响。确认后会同步解除当前项目内引用；不再满足配置要求的路由会停用，系统不会自动补入替代模型。

> **影响与边界**：影响检查结果不可用时不要继续移除。批量操作同样需要逐项确认引用和失败结果。

## 用成员视角验证是否生效

* 切换到目标成员或对应角色视角，确认模型是否可见。
* 使用属于当前项目的个人 API Key 发起一次直连调用。
* 使用路由时再验证路由目标仍然完整。
* 在调用日志中核对实际模型、接入方式和费用归属。

## 模型不可用时按层排查

依次检查企业是否可用、项目是否允许、角色是否授权、项目是否允许新调用，以及 API Key、模型或路由是否属于同一项目。不要只反复刷新模型列表。
